# 循迹功能调试日志

本文记录 LF04 四路红外模块、两轮驱动和正式循迹固件的实际调试过程。记录日期为 2026-11-12。它是本次功能实现与实车验证的证据索引，不替代赛道复测。

## 1. 安全约束

- ST-Link 3.3 V、车载电池和 Type-C 的目标板 VCC 不得同时连接。
- 本日志所述烧录与调试均在仅 ST-Link 向目标板供电、车载电源断开的状态下进行。
- 电机驱动在上电后保持 TB6612 `STBY` 低；必须短按并释放 `PB5` 才能启动循迹；长按停止。
- 需要切换为车载电源时，必须先断开 ST-Link 并确认其 3.3 V 线已拔除，之后才能接通车载电源。本次没有执行该切换。

## 2. 硬件识别与连线确认

### 2.1 LF04 接线与极性

| LF04 输出 | MCU 引脚 | 车体位置 | 结论 |
|---|---|---|---|
| `O1` | `PB12` | 最左 | 已确认 |
| `O2` | `PB13` | 左中 | 已确认 |
| `O3` | `PB14` | 右中 | 已确认 |
| `O4` | `PB15` | 最右 | 已确认 |

LF04 使用 3.3 V 供电，四路输入均从 `GPIOB->IDR` 的 bit12..bit15 单次快照读取：

```c
raw = (GPIOB->IDR >> 12) & 0x0F;
black_mask = (~raw) & 0x0F;
```

实测模块指示灯为“检测到黑线时点亮”，即低电平有效：白纸上四灯熄灭、黑线处相应灯点亮。结果如下。

| 场景 | 预期 `raw` | 预期 `black_mask` | 实测结论 |
|---|---:|---:|---|
| 白纸 | `0x0F` | `0x00` | 四灯灭，确认 |
| O1 压黑线 | `0x0E` | `0x01` | 对应左侧通道，确认 |
| O2 压黑线 | `0x0D` | `0x02` | 确认 |
| O3 压黑线 | `0x0B` | `0x04` | 确认 |
| O4 压黑线 | `0x07` | `0x08` | 对应右侧通道，确认 |
| O2、O3 同时压线 | `0x09` | `0x06` | 中心直行状态，确认 |
| 四路同时压黑 | `0x00` | `0x0F` | 十字路口候选，确认 |

探头悬空时看到全暗属于距离过大、无法接收足够反射光的正常现象；安装时应使各探头朝向赛道，使用白底/黑线完成标定，不以悬空状态作为白底判据。

### 2.2 驱动与编码器

- 两个驱动轮均已确认可同向前进。
- 实车对应关系已确认：右轮主要由 `TIM3` 编码器计数，左轮主要由 `TIM2` 编码器计数。
- 两侧编码器均能产生计数。
- 正式运行态以约 50 ms 双轮滑窗反馈为基础；反馈超过 30 ms 不新鲜、单侧 Wheel Service 无效或方向反向会分别进入反馈/方向故障路径。

## 3. 实现与策略演进

### 3.1 正式循迹入口

新增 `sc_track` 控制器，并在非 `SC_BUILD_HC05_BENCH` 的正式固件中接入：

```text
LF04 原始快照 -> sc_line_service -> sc_track_controller_step
    -> sc_wheel_target_t(mm/s) -> sc_speed_controller
    -> sc_app 安全门 -> sc_tb6612_apply/set_standby
```

控制器只输出左右有符号 `mm/s` 目标，不直接访问 GPIO 或 TB6612。正式 `main.c` 只调用 `sc_app_service()` 和只读快照/遥测；`sc_app` 是正式固件唯一调用 TB6612 PWM 与 STBY API 的模块。Bench 仍保留原有独立命令路径。

正式状态机为 `BOOT/IDLE/READY/ACTIVE/STOPPING/FAULT`。1061 CPR 台架和标定证据固化后调参、标定有效位均为 1；正式发车仍必须满足完整短按释放、双轮反馈有效、中心线路连续约 50 ms 的 6 个新鲜样本及全部故障安全门。启用顺序为 speed reset、track reset、STBY high、零 PWM、ACTIVE。

### 3.2 线型处理

| `black_mask` | 含义 | 当前动作 |
|---:|---|---|
| `0x06` | O2、O3 居中压线 | 左右同速直行 |
| `0x07`、`0x0B`、`0x0D`、`0x0E`、`0x0F` | 三路或四路同时压黑；真实十字可能因安装偏差少检测一路 | 普通循迹中按十字候选直行；已知方向找线中继续原方向搜索，不计入重捕或十字确认 |
| `0x02`、`0x04` | 轻微左/右偏移 | 微调 `850/1150`；400 mm/s 为 `340/460`，300 mm/s 为 `255/345`，200 mm/s 为 `170/230` |
| `0x03`、`0x0C` | 连续双通道偏移 | 中弯 `400/900`；400 mm/s 为 `160/360`，300 mm/s 为 `120/270`，200 mm/s 为 `80/180` |
| `0x01`、`0x08` | 大偏移或直角弯 | 大弯 `100/900`；400 mm/s 为 `40/360`，300 mm/s 为 `30/270`，200 mm/s 为 `20/180` |
| `0x05`、`0x09`、`0x0A` | 非连续双通道组合 | 按四路位置的加权重心进行微调；对称组合直行 |
| `0x00` | 四路均未检测到黑线 | 搜索 `300/900`；400 mm/s 为 `120/360`，300 mm/s 为 `90/270`，200 mm/s 为 `60/180`。方向已知时沿最近方向持续搜线，不设超时；方向未知时输出 0 并立即返回 lost |

找线状态采用低前进量、高转向差速。`recovering!=0 && last_turn_direction!=0` 表示普通已知方向找线，不另设“长时间”的门槛。在该上下文中，白帧和上述五种 junction 均清除重捕候选，保留找线方向及首次丢线时间；持续全黑超过 500 ms 仍沿原方向输出 `120/360 mm/s` 或左右镜像，不进入普通十字计时。

重捕候选仅接受有效非零、非 junction 的普通线型：至少 3 个连续新鲜样本，且首末样本时间相差至少 20 ms。新鲜度沿用相邻 sequence 不同的判定，不要求普通线型的 mask 一致。重复 sequence 清候选且本帧不计入；相邻间隔为 0、倒退或超过 30 ms 时清旧候选，并把当前帧作为新候选首帧。白帧、junction 或无效帧均中断候选。确认帧立即恢复普通线路输出，之后再遇 junction 时恢复正常十字识别。

方向未知首次全白仍立即返回 lost。正常十字保持三帧入口确认、从首个候选起算的 500 ms 总时限、100 ms 全白窗口和 200 ms 冷却；截止帧先判定三帧稳定退出，再判断超时。应用层的反馈、方向、堵转、硬件及看门狗保护不因找线状态而跳过。

### 3.3 已修复的问题

1. 初版只识别连续黑线组合。丢线后重新捕获到 `0x05`、`0x09`、`0x0A`、`0x0B`、`0x0D` 等非连续组合时，程序会误判异常并停车。
   - 修复：用四路加权重心处理全部非零合法掩码，不再因这些组合停止。
2. 初版丢线找回持续 500 ms，无法覆盖传感器间距较大或弯道的短时全白状态。
   - 历史修复：曾把普通找回窗口改为 1000 ms；当前普通已知方向搜索已取消总超时，未知方向和十字时限仍保留。
3. 丢线找回时车辆会以大半径转一圈。
   - 修复：搜线内侧轮改为极低输出、外侧轮保留转向输出，形成更紧凑的找线弧线。
4. 十字路口四路全亮时可能选择横向路径；落地又发现四路不一定同时触发。
   - 修复：最初将 `black_mask=0x0F` 固定左右同速；落地记录显示十字处先出现 `0x0E`，旧策略把它当作全右转并丢线。现在三路压黑的 `0x07/0x0B/0x0D/0x0E` 与 `0x0F` 统一按十字直行。
5. 上电已按住的按键释放曾被误认为新的发车短按。
   - 修复：Button Driver 以当前原始电平作为初始化稳定态；App 只接受完整 PRESSED -> RELEASED，并忽略孤立 RELEASED。
6. 旧运行保护只检查“两轮都完全不动”，无法发现单轮堵转或错误方向。
   - 修复：每侧独立使用 300 ms 固定窗口净进展。目标至少 50 mm/s 且已提交 PWM 至少 150 时，按目标、实际时间、每转计数和轮径计算理论计数，净进展不足 20% 即锁存该轮堵转。单帧 `+1` 抖动不能重置窗口。
7. 正目标控制回调到负 PWM 时曾被错误地并入方向异常判断。
   - 修复：只有目标与控制器命令同号且物理计数反向时，才把 3 个新 sequence 累计为方向 FATAL。
8. 可恢复故障曾可能在持续全白时仅靠 200 ms 健康计时清位。
   - 修复：健康条件必须为有效非白线路；`LINE_LOST` 还必须重新看到中心 `0x06` 并完成稳定窗口。清位后仍需新的完整短按才可再次运动。

## 4. 速度调参记录

循迹目标由 `cruise_mm_s` 乘固定整数比例并四舍五入。下表以历史巡航基准 `396 mm/s` 展示等价目标，实际正式巡航速度由 App 配置。

| 阶段 | 中心直行历史基准 | 结果与后续决策 |
|---|---:|---|
| 初始实现 | `299/1000` | 可循迹，随后按实车需求加速 |
| 第一次加速 | `449/1000` | 约为初始速度的 1.5 倍；弯道动态误差增大 |
| 灵敏度修正 | `449/1000` | 加大偏移差速、急弯内侧停轮、搜线收紧 |
| 降至 0.8 | `359/1000` | 保留全部差速比例 |
| 提升至 1.2 | `431/1000` | 实车反馈精度下降 |
| 上一历史版本 | `396/1000` | 为更早版本的 0.92，旧转向比例仍会横摆 |
| 本轮候选 | `400/1000` | 差速比例改进后左右振荡已改善；普通已知方向失线改为持续搜索，400 mm/s 尚待实车 |

当前候选目标（`mm/s`）如下，左右互换时用于相反方向。`0x06` 与微调 `0x02/0x04` 语义不变；这些数字是目标轮速，不是实测轮速或 PWM。

| 状态 | 400 mm/s 左/右 | 300 mm/s 左/右 | 200 mm/s 左/右 |
|---|---:|---:|---:|
| 中心直行/十字直行 | `400/400` | `300/300` | `200/200` |
| 轻微左/右偏 | `340/460`、`460/340` | `255/345`、`345/255` | `170/230`、`230/170` |
| 中度左/右偏 | `160/360`、`360/160` | `120/270`、`270/120` | `80/180`、`180/80` |
| 大幅左/右偏 | `40/360`、`360/40` | `30/270`、`270/30` | `20/180`、`180/20` |
| 向左/右搜线 | `120/360`、`360/120` | `90/270`、`270/90` | `60/180`、`180/60` |

PWM 由正式速度控制器产生并经电机符号换算后提交；当前 400 mm/s 候选只完成软件基线、28 项 CTest 和 33 项缺陷变异验证，尚待实车确认。PID、两层速度斜坡和 PWM 上限 564 未改，正式配置仍受按键、线路、反馈和故障安全门约束。

### 5.3 正式遥测与 IWDG

- IWDG：先启动 LSI，再解锁写 PR/RLR；更新位等待有上限，超时进入紧急停机和错误处理。LSI 名义 40 kHz、`/64`、重装 312，名义期限 0.4992 s；实际期限依赖 LSI 容差。
- 正式与 Bench 主循环均初始化 IWDG，并在核心采样、状态推进和安全提交完成后喂狗。受控 FAULT 仍可喂狗，必须由用户处理或断电重启。
- HC-05 以 9600 8N1、5 Hz 发送 `time_ms,phase,raw,mask,target_l,target_r,measured_l,measured_r,pwm_l,pwm_r,stby,fault,degraded`。
- OLED 以 2 Hz 显示阶段、线路、目标、实测、PWM、STBY、停止原因和故障位；异步 Service 后读取状态和重试计数，任何异步失败只置显示降级位。
- 本次只验证代码与构建，没有在目标板上确认 5 Hz 串口时序、OLED 实际刷新和 IWDG 复位波形。
- 十圈及补测结果：左轮 `10602/10617`，中位 `1060.95 -> 1061 CPR`，离散 `0.14%`，正转原始总数为负并匹配 `-1`；右轮 CPR 样本 `1057.70/1085.10/1060.20/1061.30/1061.40`，中位 `1061.30 -> 1061`，其中 `1085.10` 为离群，其余集中；右轮正转原始总数为正并匹配 `+1`。CPR 更新使旧 1040 及右轮 1060 候选阶段下的 200/500 mm/s 结果失效。
- 1061 CPR 新标尺 Identify 日志 `20261113-121905`：`vL396=489 mm/s`、`vR396=486 mm/s`，离散度均 `1.0%`，固化 `FF_L=810/FF_R=815`。200/500 mm/s 各三轮闭环均通过，每轮 201 个 2 秒样本，无饱和/fault；`TUNING_VALID=1`。标定依据为 48.600 mm 卡尺、十圈中位、编码器符号和正命令两轮向前；落地有效滚动周长未测但由用户豁免，因此 `CALIBRATION_VALID=1`。Bench 的 `PARAM=UNVERIFIED` 仅表示台架/豁免边界，不表示正式 VALID 为 0。
- 落地循迹诊断：正式默认 500 mm/s 时，中心段右轮可接近 500 mm/s，但左轮 PWM 长期达到 564‰ 上限，实际仅约 160..200 mm/s；车辆随后因左右差速离开中心线并触发 `LINE_LOST`。降至 200 mm/s 后又以 300 mm/s、PID 增益不变的配置做对照：两轮曾达到约 262/262 mm/s，输出仍有余量，但约 1.2 秒内出现 `mask 8 -> 4 -> 0` 横向振荡并丢线。本轮回退到 200 mm/s；失败证据指向循迹目标切换/转向响应，而不是速度环输出饱和，暂不修改 PID。
- 200 mm/s 十字诊断：十字处先看到 `0x0E`，后续 5 Hz 记录帧出现 `0x02/0x04` 和全白；单帧直接锁存会在普通弯道或误识别时长时间屏蔽转向。现已改为独立 CROSSING 状态：连续 3 个新鲜 junction 样本才进入，最大直行 500 ms 且不续期，全白独立限制 100 ms；连续 3 个新鲜中心或同掩码普通样本才提前退出，左右交替的 `0x02/0x04` 被拒绝为不稳定。超时未确认一律停车，并有 200 ms 防重入冷却。当前状态机及本轮严重转向候选共通过 28/28 循迹回归和 33/33 缺陷对照，仍待实车复测。
- 200 mm/s 落地十字诊断：运行中未看到四路同时压黑的 `0x0F`，十字附近实际出现 `0x0E`。旧策略按全右转输出约 `285/0 mm/s`，下一帧进入全白并触发 `LINE_LOST`。现已将三路及四路压黑统一直行，新增“三路压黑漏检”回归与缺陷对照，尚待再次落地验证。
- 历史速度上探记录：旧比例下 300 mm/s 约 1.2 s 后横向振荡并丢线；400 mm/s 在单个前万向轮底盘上约 7 s 后出现 `0x08/0x02/0x04/0x00` 连续左右振荡并触发 `LINE_LOST`。该结果属于旧转向比例，不能用于评价当前候选。

### 5.5 恢复态全黑误停与振荡定位（2026-11-13）

本轮保持巡航 400 mm/s、左右 PI `100/750/0`、前馈 `810/815`、PWM 上限 `564‰`、目标斜坡 `2000 mm/s²` 和输出斜坡 `8000‰/s`。不新增正式固件 RX 入口、在线调参或高频采集功能。修复、软件验证与烧录状态分别记录，不把旧台架数据当作当前赛道验收。

**已确认的误停路径。** 修改前的 `sc_track` 把找线中的所有非零 mask 都当作重捕证据。三帧全黑可能结束找线，随后进入普通十字；十字输出又清除原找线方向，持续 junction 最终触发 500 ms 时限。这与 `build/telemetry/trace-400-infinite-search-20261113-163359.csv` 中的下列记录一致：

|---:|---|---:|---:|---|
| 164704 | ACTIVE | 0 | 120/360 | 0 |
| 164904 | ACTIVE | 15 | 400/400 | 0 |
| 165104 | ACTIVE | 15 | 400/400 | 0 |
| 165304 | FAULT | 15 | 0/0 | `0x00000002` |

同一日志还记录了持续三黑 `mask=7` 后在 221104 ms 进入 `LINE_LOST`，因此恢复分流覆盖全部五种 junction，避免三黑先结束恢复再遇全黑的同类缺口。日志为 5 Hz，不能从相邻两行精确还原 10 ms 状态机入口时刻；500 ms 路径由源码及对应主机回归核对。另一次 117304 ms 的 `0x00000040 STALL_RIGHT` 单独保留，不作为取消堵转保护的依据。

**振荡诊断的事实与边界。** 四路循迹外层目前按 mask 切换固定差速比例，没有独立的循迹 PID；轮速内环才是左右独立的 PI 加线性前馈。目标从 40 跳到 460 mm/s 时，按 `2000 mm/s²` 目标斜坡需要约 210 ms，尚未包含机械响应；反馈是约 50 ms 的滑动计数窗口，每个新编码器样本更新。若目标在此期间反复改变方向，目标斜坡和反馈滞后都可能参与横摆，但现有 5 Hz 数据不足以确定各自贡献或定量选择增益。

既有 1061 CPR 悬空验收覆盖 200/500 mm/s，没有在同一组验收中覆盖当前大弯内轮 40 mm/s 和搜索内轮 120 mm/s。前馈由悬空固定 PWM 的速度数据确定，低速死区、当前接地负载及底盘变化下的误差仍待测量；这些是待验证原因，尚不能判定为本次振荡根因。

作为已测基线的一次复核，`build/tune-logs/step-left-20261113-122345.csv` 与对应 right CSV 经 `pid_lab.py analyze --control-limits -564 564 --settling-band 50` 分析：500 mm/s、2 s、每轮 201 点；左右末段 MAE 为 10.5875/14.1875 mm/s，峰值超调 6.0%/7.6%，进入并保持 ±10% 为 0.31/0.31 s，无饱和。对应 meta CSV 和原始 STATUS 日志确认当时 PI 为 `100/750/0`、FF 为 `810/815`。该结果仅对应当次悬空试验，不外推为当前落地响应。

**下一轮需要的测量。** 在相同供电、负载和参数条件下，以 100 Hz 同步记录时间、左右原始目标、斜坡后目标、实测轮速、实际提交 PWM、mask、找线/十字状态及故障位，重点覆盖 40/120 mm/s 低速段和目标反向切换。按每次启动、目标变化及参数回读分段：先查目标是否先反转，再查恒定斜坡后目标下的速度误差与饱和，分别评价外层转向和内层轮速。采集阶段只缓存，停车后经 HC-05 分块导出，不以 9600 baud 实时发送完整 100 Hz 样本；原始日志保留，低频正式遥测不替代该采样。本轮仅记录需求，不实施采集或候选增益更新。

## 6. 当前使用方法

1. 保持单一供电源。烧录/调试时仅接 ST-Link；运行赛道前先断开 ST-Link 再接车载电源。
2. 将车放在白底黑线赛道，确保 O2、O3 位于黑线附近。
3. 在标定和调参完成、两个 VALID 都改为 1 后，保持中心线连续约 50 ms 并短按释放 PB5，正式循迹开始。
4. 任意时刻长按 PB5，车辆执行 speed stop -> 零 PWM -> STBY low；未知方向首次全白、十字确认后丢线、反馈陈旧或调度异常进入可恢复 FAULT，普通已知方向全白持续搜索。下一次运动仍需新的完整短按。
5. TB6612/HAL/方向 FATAL 不能被按键清除，必须断电重启；IWDG 复位后同样回到 BOOT/IDLE，不自动续跑。

# 双轮速度控制实现与实验记录

## 1. 当前状态

截至 2026-11-13，`sc_wheel_service`、`sc_pid`、`sc_speed_controller` 已实现并通过主机测试，但尚未接入主循环、循迹控制、应用安全门或 HC-05 Bench。当前没有任何实车闭环调参记录，也没有已验证的控制增益。

## 2. 控制器语义

- 控制器形式：并联 PID。
- `kp_milli=1000` 表示 `1 PWM permille / (mm/s)`。
- `ki_milli=1000` 表示 `1 PWM permille / mm`。
- `kd_milli=1000` 表示 `1 PWM permille / (mm/s^2)`。
- `ff_milli=1000` 表示 `1 PWM permille / (mm/s)`。
- PID 使用相邻有效反馈的实际 `dt_ms`，微分作用于测量值；首帧和 reset 后不产生微分项。
- 外部目标为 0 时，该侧目标斜坡值和实际控制输出立即归零，并清除该侧积分与微分历史；另一侧继续按自身目标控制。
- 条件抗饱和同时检查输出限幅，以及输出斜坡后的实际提交值；未完整提交的正/负积分增量被冻结。
- 目标先经过 `2000 mm/s^2` 斜坡，再加上前馈并进入 PID；最终输出经过 `8000 permille/s` 斜坡和 `-564..564` 限幅。

## 3. 轮速窗口

- 编码器每约 10 ms 产生快照。
- Wheel Service 每侧保存最近 6 个有效快照，对应最近 5 个时间差；热身后每来一个约 10 ms 新快照就更新一次约 50 ms 滑窗速度。
- 速度由窗口首末累计总计数差除以实际时间计算，不平均已取整的单帧速度。
- 重复 sequence、30 ms 以上陈旧快照、`interval_ms=0` 重置帧、任一侧 lost_sync 或无效数据均不会形成一个有效的双轮闭环反馈。
- 左右窗口和有效位独立更新；整体有效位要求左右均有效。

## 5. 已完成的实验证据

- 数据来源：主机单元测试与手算向量，不是实物响应日志。
- Wheel Service：8/8；缺陷对照 6/6 在目标断言失败。
- PID：6/6；缺陷对照 4/4 在目标断言失败。
- Speed Controller：9/9；缺陷对照 6/6 在目标断言失败。
- 新模块通过 GCC `-fanalyzer`。
- 全量 11 个现有测试套件通过，共 130 个基线测试。
- Debug、Release、Bench 均完成交叉编译；模块未接入主循环，链接后 RAM/Flash 净增为 0 B。

## 6. 下一阶段测量计划

1. 抬轮确认左右编码器符号，人工转动 10 圈核对每转计数和轮径。
2. 固定 PWM 做开环前进/后退阶梯实验，记录左右实际 `mm/s` 与稳态 PWM。
3. 根据开环数据更新前馈和占位增益，一次只改变一个有明确依据的参数。
4. 使用 `timestamp_ms,setpoint,input,pwm,p,i,d,p2,i2,d2` 的正规化日志，保留 session、round、mode、实际加载参数和读回状态。
5. 在实车实验前由用户定义尾误差、超调、稳定窗口和实验次数；未定义前不宣称收敛或“已调好”。
